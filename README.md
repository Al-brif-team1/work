# AI Assistant

Python-ядро для анализа внешних брифов заказчиков на студенческие проекты
«Мастерской».

Система загружает и нормализует один бриф, извлекает структурированные факты с
помощью LLM, детерминированно проверяет полноту данных, выполняет один
объединённый LLM-этап `Assessment`, применяет настраиваемые правила арбитража,
генерирует уточняющие вопросы по шаблонам, при необходимости формирует MVP-план
и возвращает структурированный JSON.

## Пайплайн

1. `BriefInputFactory` загружает текст или UTF-8 файл и нормализует пробелы.
2. `Extractor` извлекает фактические данные в `ExtractedBrief`.
3. `CompletenessCheckStage` проверяет обязательные поля из `config/criteria.yaml`.
4. `AssessmentStage` оценивает критерии и риски за один LLM-вызов.
5. `DeterministicArbiterStage` вычисляет итоговую рекомендацию по правилам.
6. `TemplateQuestionGeneratorStage` генерирует вопросы без LLM-вызовов.
7. `MVPPlannerStage` вызывает LLM только если Arbiter вернул `SIMPLIFY`.
8. `ResponseWriterStage` детерминированно формирует черновик ответа заказчику на русском языке.

Типичная стоимость LLM:

- Готовый бриф или бриф с уточнениями: `Extractor` + `Assessment` = 2 LLM-вызова.
- Бриф, которому нужно упрощение: `Extractor` + `Assessment` + `MVPPlanner` = 3 LLM-вызова.

## Конфигурация

Создайте `.env` на основе `.env.example`:

```env
# Провайдер LLM. Подходит любой OpenAI-совместимый API — адрес задаётся явно.
LLM_API_KEY=your_key
LLM_MODEL=openai/gpt-4o-mini
LLM_BASE_URL=https://openrouter.ai/api/v1

LANGFUSE_PUBLIC_KEY=
LANGFUSE_SECRET_KEY=
LANGFUSE_HOST=https://cloud.langfuse.com
DEBUG=false
LOG_LEVEL=INFO
```

Обязательны только `LLM_API_KEY`, `LLM_MODEL` и `LLM_BASE_URL` — без них приложение
не стартует.

### Настройка вызовов LLM

Эти переменные необязательны: у каждой есть значение по умолчанию в `Settings`.
Держите в `.env` только те, что действительно отличаются от дефолта — иначе значение
окажется записано дважды, и `.env` будет молча перекрывать код. Полный список
с пояснениями лежит в `.env.example`.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `LLM_TEMPERATURE` | `0.0` | Насколько случаен выбор слова, от `0` до `2` |
| `LLM_MAX_TOKENS` | не задан | Предел длины ответа |
| `LLM_TOP_P` | не задан | Отбрасывает маловероятные слова, от `0` до `1` |
| `LLM_MAX_ATTEMPTS` | `2` | Число попыток запроса |
| `LLM_TIMEOUT_SECONDS` | `60.0` | Таймаут одной попытки |
| `LLM_TRANSPORT_RETRIES` | `0` | Повторы внутри SDK `openai` |

Пустое значение не означает «по умолчанию»: строка `LLM_MAX_TOKENS=` не пройдёт
валидацию и приложение не запустится. Чтобы остаться на дефолте, уберите строку
целиком или закомментируйте её.

#### `LLM_MAX_TOKENS` и `LLM_TOP_P` — про разное

`LLM_MAX_TOKENS` управляет **длиной**. Это жёсткий предел: дойдя до него, модель
обрывает ответ на полуслове. Она не начинает писать короче — её просто прерывают.
Для этого проекта важно, что все этапы просят структурированный JSON: обрыв даёт
не короткий ответ, а сломанный JSON, запрос уходит на повтор и в итоге падает
с ошибкой. Ставьте значение с запасом — это страховка от неожиданно длинного
ответа и лишних трат, а не способ управлять стилем.

`LLM_TOP_P` управляет **выбором слова** и на длину не влияет никак. На каждом шаге
модель прикидывает вероятность каждого возможного следующего слова и выстраивает
их от самого вероятного к самому редкому. Значение `0.9` означает: бери варианты
с начала списка, пока их суммарная вероятность не наберёт 90%, а весь оставшийся
«хвост» редких слов отбрось и выбирай только из отобранных. Чем меньше значение,
тем предсказуемее и суше текст; `1.0` не отбрасывает ничего.

Учтите, что `LLM_TOP_P` и `LLM_TEMPERATURE` управляют одним и тем же — случайностью
выбора, поэтому менять принято что-то одно. При нашем дефолте `LLM_TEMPERATURE=0.0`
модель и так каждый раз берёт самое вероятное слово, так что `LLM_TOP_P` в этой
конфигурации практически ни на что не влияет.

Две настройки легко перепутать:

- `LLM_MAX_ATTEMPTS` — **общее** число попыток, а не число повторов: при `2` уходит
  два запроса, а не три.
- `LLM_TRANSPORT_RETRIES` — ретраи внутри SDK `openai`, поверх наших попыток. При `0`
  за повторы отвечает один слой и таймаут считается честно; при `2` (прежнее поведение
  SDK по умолчанию) один неудачный вызов может обернуться шестью запросами к провайдеру.

Критерии проекта, обязательные поля, типы рисков и правила арбитража находятся здесь:

```text
config/criteria.yaml
```

Шаблоны уточняющих вопросов находятся здесь:

```text
config/question_templates.json
```

Русские названия обязательных полей брифа находятся здесь:

```text
config/field_titles.json
```

Бизнес-критерии намеренно вынесены в конфигурацию и не зашиты жёстко в промпты
или Python-логику принятия решений.

`config/criteria.yaml` — внутренний англоязычный конфиг. Его `title` и `description`
нужны для отладки и трассировки и не должны попадать в текст, который читает заказчик:
письмо и публичный результат собираются из русских формулировок оценки и из
`config/field_titles.json`.

## Запуск

Анализ текста из командной строки:

```bash
python -m app.main --text "Нужно сделать сайт для образовательного проекта..."
```

Анализ UTF-8 файла:

```bash
python -m app.main --file examples/brief.txt
```

Только нормализация ввода без вызова LLM:

```bash
python -m app.main --text "Текст брифа" --normalize-only
```
